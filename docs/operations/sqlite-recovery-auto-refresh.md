# SQLite 数据保护自动保鲜

配置 `SQLITE_RECOVERY_AUTO_REFRESH_ENABLED=true` 后，当前 Nest 进程会在启动后异步检查一次，并按固定的一小时周期检查现有 recovery 状态。默认关闭；关闭时不会创建定时器，也不会自动执行备份。

自动任务只在以下两种状态调用现有 `SqliteRecoveryOperationsService`：

- `no_backup`：恢复状态目录可读，但没有有效备份。
- `recoverable` 且 `freshness=stale`：已有验证通过的备份，但超过新鲜度窗口。

`backup_unverified`、`drill_failed`、`unavailable` 和 `recoverable + fresh` 不会自动操作。自动任务与 Owner 手动操作共享同一进程内互斥锁；遇到手动操作正在运行时，本轮自动检查会安全跳过。真实自动失败后，当前进程会暂停后续自动执行，保留人工检查入口，不做自动重试或退避。

自动任务不写 Staff OperationLog，也不伪造系统员工身份。结构化日志只记录事件阶段和白名单状态/错误码，不记录路径、文件名、哈希、数据库连接、堆栈或业务数据。

## Owner 运行态

Owner 数据保护卡会显示自动保护是否启用。启用时还会显示当前进程内的运行态：

- 最近一次自动检查时间；
- 最近一次结果：成功、备份新鲜而跳过、不满足条件、任务忙、失败或失败抑制；
- 白名单原因码；
- 失败抑制是否生效；
- 下一次真实定时检查时间。

运行态只保存在当前进程内，不写数据库、不写新表。进程重启后会回到“尚未执行”，长期历史仍以结构化日志为准。关闭自动保护时，不显示虚假的下一次检查时间。

后台刷新数据保护状态时，会同时重新读取持久化 recovery 状态和当前进程运行态。Operator 不显示 Owner 数据保护卡。

本能力是单实例进程内自动保鲜，不是完整的备份调度平台；不包含 cron 配置、队列、Redis、多实例协调、备份保留策略、对象存储、异地备份、加密或自动恢复生产数据库。
